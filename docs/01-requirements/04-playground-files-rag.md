## [变更] 立项排期（2026-08-22）

- **变更原因**：发送框现在只能贴图片；用户会复制 PDF/文档。没有稳定 RAG 时，把整份文件塞进对话会炸掉 Token、也检索不准。
- **决策**：
  1. **现在不做**通用文件（PDF / Word / TXT / MD / HTML）进对话
  2. **阶段十三**再做，前置条件是 RAG 闭环没问题
  3. 文件不走 vision 附图，走知识库解析 → 分块 → 向量 → 对话时检索

---

## 1. 一句话

图片继续直接发给识图模型。  
PDF 这类文件：**等知识库 RAG 稳了**，再在发送框里粘贴/上传，自动入库检索，回答时只带相关片段。

## 3. 开工门槛（RAG 完全没问题）

下面**全部**满足才能开工阶段十三，缺一项就继续只支持图片：

1. 知识库上传 → 解析分块 → 向量写入 **稳定可重复**（失败有明确状态，可重试）
2. **Embedding 与聊天模型分开**（DeepSeek 只开 Chat 时向量化不能挂，见已知问题「无 embeddings」）
3. 检索是 **向量语义检索**，不是关键词凑合；有命中片段和分数
4. Playground / Agent 提问能 **按知识库召回片段** 再问模型，空库/无命中有人话提示
5. 配额：知识库 embedding **不算**用户对话额度（已有约定，落地时别改坏）

---

## 4. 阶段十三要做什么（到时再写细设计）

- 发送框：粘贴/拖入/选择文件；排队条目可带附件引用（不只 `images`）
- 文件进会话级或用户知识库（二选一或都做，开工时定）
- 解析复用现有知识库管道，不另写一套
- 发消息时 RAG 检索 Top-K 片段注入上下文
- 气泡展示文件名，不展示整份 base64

---

## 5. 明确不做（直到门槛满足）

- 把 PDF 当图片发给 vision
- 把整份文档 base64 塞进 `messages`
- 在 RAG 还报错、还没有独立 embedding 时硬上文件附件
