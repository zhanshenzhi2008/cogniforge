# Cursor 开发规则（Development Rules for Cursor Workflow）

## 1. 文档驱动开发（Documentation-Driven Development）

所有功能、接口、架构变更必须遵循 `docs/` 目录结构，并执行以下原则：

### 1.1 必须保持文档与代码一致

-   无论后端、前端、架构、数据库，只要代码有变动：
    -   必须更新对应文档\
    -   文档落后于代码视为 **Bug**\
    -   代码变更没有文档更新 **禁止合并到主分支**

### 1.2 文档目录说明

    docs/
    │
    ├── 01-requirements
    │   └── 01-product-requirements.md
    ├── 02-architecture
    │   └── 01-technical-architecture.md
    ├── 03-api
    │   └── 01-api-design.md
    ├── 04-database
    │   └── 01-database-design.md
    ├── 05-frontend
    │   └── 01-frontend-design.md
    ├── 06-devops
    └── 99-dev-plan
        ├── 01-development-plan.md
        ├── 02-project-structure.md
        └── 03-known-issues.md

所有改动必须找到对应模块，不存在则新增。

------------------------------------------------------------------------

## 2. 文档变更规则（Change Documentation Rules）

### 2.1 修改原文档的方式

当文档内容不再适用，需要废弃或替换时：

~~原规则：xxx~~\
**变更：2026-04-01**\
新规则：yyyy

### 2.2 新增章节格式

    ## [变更] Add 新功能名称（2026-04-01）
    变更原因：xxxx  
    包含代码：xxx  
    影响范围：xxx  

### 2.3 API 文档与代码必须同步

后端任何变更必须同步更新： - method\
- path\
- request body\
- response body\
- status code\
- 错误码

若 API 实现已变更而文档未更新，该 PR 直接拒绝。

------------------------------------------------------------------------

## 3. 开发工作流（Cursor + Git）

### 3.1 开发前

-   在 Cursor 内输入你的全局 Rules 让 AI 自动遵守。

-   创建新分支（禁止在 main 上直接开发）

        git checkout -b feature/xxx

### 3.2 开发中

如果变更代码 → 必须更新相关 docs\
如果修改架构 → 更新 `02-architecture`\
如果修改 API → 更新 `03-api`\
如果修改数据库结构 → 更新 `04-database`\
如果修改前端结构 → 更新 `05-frontend`

Cursor 生成代码时必须提醒： \> "请同步输出需要更新哪些文档。"

------------------------------------------------------------------------

## 4. Git 提交规范（Commit Rules）

使用 **Conventional Commits**：

-   `feat:` 新功能\
-   `fix:` 修复问题\
-   `refactor:` 重构但无行为变更\
-   `docs:` 文档变更\
-   `chore:` 任务调整\
-   `style:` 格式化\
-   `perf:` 性能优化\
-   `test:` 测试相关

示例：

    feat: 实现用户登录 API 并更新 API 文档

    - 新增登录接口 /api/login
    - 更新 docs/03-api/01-api-design.md
    - 更新用户数据库表结构文档

注意：\
AI 生成 commit message 后，只给文本，不执行 git commit。

------------------------------------------------------------------------

## 5. 可选增强（Coding Spec 建议）

### 5.1 使用 ADR（Architecture Decision Record）

新增：

    docs/02-architecture/adr/

示例：

    # ADR-0001: 选择 Redis 作为缓存方案
    日期：2026-04-01
    决策原因：xxx
    备选方案：xxx
    最终决策：xxx

### 5.2 自动文档检查（可选）

加入 Git Hooks 检查： - diff 是否涉及 API/db 变更\
- 若变更但文档未更新 → 阻止提交

### 5.3 Cursor 自动规约 Prompt

    如果我修改代码，请提醒我同步更新文档。
    如果我开发 feature，请提醒我补充 API、数据库、架构、前端文档。
    所有改动请指出需要更新的文档路径。
    生成 commit message 但不要执行 git commit。
