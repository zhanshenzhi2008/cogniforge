## [变更] 立项锁定（2026-08-21）

- **变更原因**：流式中无法连问；改中间一问需要可控截断
- **决策**：
  1. 排队 / 插入含义已确认
  2. 插入后旧内容：**硬截断 + 确认**（不做 ‹ › 分支树；分叉新会话留二期）
  3. 流式中 **Enter = 加入排队**
  4. 排队条目：**可编辑、可删除、可调序**；「发送中」锁定

---

## 1. 一句话

- **排队**：AI 还在答时，下一条先进队，答完自动发；队里能改字、能删。
- **插入**：在某条消息后插一问，**删掉后面所有消息**（先确认），再发新问题。

---

## 2. 排队

| 规则 | 说明 |
|------|------|
| 入队 | 流式中 Enter，或点「加入排队」 |
| 上限 | 每会话最多 **5** 条 |
| 状态 | `queued`（可改删调序）/ `sending`（锁定） |
| 编辑 | 点正文；Enter=保存回队列（不发送）；Esc=取消 |
| 删除 | `queued` 直接删，无二次确认 |
| 调序 | ↑↓ 或拖拽（一期可用 ↑↓） |
| 持久化 | 存在 `chat_conversations.message_queue`，刷新不丢 |
| 插入时 | **清空**本会话排队，避免截断后自动发旧队 |

流式结束后：取队首 → `sending` → 当作用户消息发出 → 成功后出队继续下一条。

---

## 3. 插入（方案 A）

1. 用户消息 hover →「在此后插入」
2. 出现插入草稿条
3. 确认：「将删除此条之后的 N 条消息，不可恢复」
4. 截断 `messages` → 追加新用户消息 → 清空 queue → 开始生成 → 存档

---

## 4. 数据

`message_queue` JSONB 元素：

```json
{ "id": "uuid", "content": "...", "images": [], "status": "queued", "sort": 0 }
```

API：`GET/PUT /api/v1/conversations/:id` 读写 `message_queue`；列表摘要可不带队列正文。
