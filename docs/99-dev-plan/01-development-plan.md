### 知识有效期、密级与检索过滤（2026-11-25，未做）

**现状**：文档现有 `status` = 解析流水（pending/processing/completed/failed）；无业务生命周期态；无 `effective_at` / `expire_at`；无知识密级与人侧 clearance；RAG / 工作流 search / 检索测试均不按状态、时间窗、密级过滤。

**设计原则**

- **两套能力可叠加，不是二选一**：① 可见范围 + 状态 + 有效期（通用）；② 安全等级（金融扩展）。
- **有知识密级，必须有人侧「最高可访问密级」**，否则密级只是摆设。
- **部门**优先当「可见范围 / 归属」，不要和密级混成同一字段；密级优先挂在**角色**，人员做特例覆盖。

#### A. 通用必做（个人 / 中小团队也适用）

**业务状态（固定枚举）**

| 中文 | 建议字段值 | 说明 |
|------|------------|------|
| 草稿 | `draft` | 编辑中，默认不进检索 |
| 审核 | `review` | 待审，默认不进检索 |
| 发布 | `published` | 可检索（仍受生效/失效时间约束） |
| 废止 | `abolished` | 下线，不进检索 |

> 解析进度与业务状态**分字段**，避免「处理中」和「审核中」挤在同一个 status。

- [x] 文档增加业务状态（草稿/审核/发布/废止）+ 生效时间、失效时间（空=不限）
- [x] 管理页可改状态与时间窗；列表展示业务状态
- [ ] 可见范围继续用库级 `visibility`（private / org…）；组织共享按原规划推进
- [x] 检索默认只返回：**发布** + 当前时刻在有效期内 的文档分块
- [x] 对话 RAG、工作流 search 节点、知识库检索测试共用同一过滤规则
- [x] 检索可选 `include_drafts` / `ignore_validity`（API + 检索测试侧栏开关）

#### B. 金融扩展（银行 / 强合规；通用版可隐藏）

**知识密级（建议四级）**

| 中文 | 建议字段值 |
|------|------------|
| 公开 | `public` |
| 内部 | `internal` |
| 机密 | `confidential` |
| 绝密 | `secret` |

**人侧 clearance（与知识密级成对）**

| 挂载点 | 建议 | 说明 |
|--------|------|------|
| 角色 | **优先做** | 如客服/柜员/客户经理/风控/合规 → 各有 `max_security_level` |
| 人员 | 可选 | 特批/借调时覆盖角色上限 |
| 部门 | 不做密级主字段 | 用可见范围/归属表达「哪个分行/部门能进库」 |

- [x] 文档可设 `security_level`（预览 + lifecycle API）；默认 `internal`（上传默认靠列默认）
- [x] 谁有权把文档抬到「机密/绝密」单独鉴权（clearance≥目标或 admin）
- [x] 角色增加 `max_security_level`；人员可覆盖（用户管理 UI）
- [x] 检索强制：`人的可用密级 ≥ 知识密级`（`KB_ENFORCE_SECURITY_LEVEL` 开关；默认关）
- [x] 改文档密级、角色/用户 clearance、密级强制检索留审计日志（`security_audit_logs` + 监控 Tab）
- [x] 通用版 UI 隐藏密级；`NUXT_PUBLIC_SHOW_SECURITY_LEVEL=1` 才展示

#### C. 检索总规则（金融全开时）

> 能进该库（可见范围） **且** 人的可用密级 ≥ 知识密级 **且** 文档状态=发布 **且** 当前在有效期内 → 才可被召回

#### D. 中期 / 按需

- [ ] 库级是否需要整体生效窗（多数场景文档级即可）
- [ ] 向量侧元数据同步密级与有效期（过滤下推，少召回再丢弃）
- [ ] 导出 / 下载同样走密级与审计（不只检索）
